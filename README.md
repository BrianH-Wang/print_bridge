# Print Bridge (V1.0.0)

**中文** | [English](README.en.md)

一个跨平台（Windows / macOS / Linux）的**本地打印与数据中转服务**，带 PyQt6 图形界面。

它解决的问题是：浏览器 / Web 页面无法直接调用本机打印机，也无法直接接收第三方系统的回调数据。本程序作为常驻本机的"桥梁"，一端用 WebSocket 与前端页面通讯，另一端调用系统打印机并接收外部 HTTP 回调。

## 主要功能

程序由两个可独立开关的模块组成，在界面上勾选启用。

> **前端只需连一条 WebSocket**（默认 `ws://localhost:8765`，端口在「前端连接」卡片配置，可选 8000–65535）。
> 打印和数据推送**共用这一条连接**，因此只要勾选了任意一项功能，WebSocket 服务就会启动 ——
> 即使不用打印机、只用「获取数据」，前端一样连得上、收得到数据。

### 1. 自动打印 🖨

- 前端页面连接后，把 PDF 以**二进制帧**发过来，服务端保存到系统临时目录（文件名带时间戳，不会互相覆盖），再调用系统打印机打印：
  - Windows：`win32api.ShellExecute(..., "print", ...)`
  - macOS / Linux：`lp -d <打印机名>`
- 打印结果通过 `{"type": "print_status", "data": "✅ 成功" / "❌ 失败"}` 回传给前端。
  未勾选「自动打印」时若收到 PDF，会回 `"❌ 未启用自动打印"` 并忽略，不会尝试打印。
- 前端可先发一条 `{"type": "printWithTime", "timeInfo": {...}}` 文本消息带上耗时信息（`apiTime`、`prepareTime`、`startTime`），服务端据此在日志中统计接口耗时、准备耗时和端到端总耗时。
- 打印机列表自动枚举（Windows 走 `win32print`，macOS/Linux 走 CUPS），并预选系统默认打印机。

### 2. 获取数据 🌐（HTTP 回调接收）

- 在 `localhost:13213/callback` 启动一个 HTTP 服务，接收外部系统 `POST` 过来的 JSON 数据。
- 收到后立即广播给**所有**已连接的前端：
  `{"type": "external_data", "data": <原始 JSON>}`
- 对调用方返回统一 JSON 响应：成功 `{"success": true, "code": 200, "forwarded": <推送客户端数>}`，解析失败 `{"success": false, "code": 400, "error": ...}`。
- 另提供 `GET` 健康检查，返回当前在线的 WebSocket 客户端数。

### 界面

- 功能开关、端口 / 打印机配置、启动/停止按钮、状态提示。
- 底部分「日志输出」「接收历史」两个页签。
- 日志：各服务线程通过 `queue.Queue` 把日志推给 GUI，界面每 300ms 批量刷新一次，最多保留 2000 行；可切换自动滚动、一键清空。
- **接收历史与重发**：每条从 `/callback` 收到的数据都会记进表格，最新的在最上面，最多保留 200 条，页签标题实时显示条数。
  - 列是**按收到的字段动态生成的**：「时间」在最左，「图片」「推送」在最右，中间每个 JSON 字段各占一列（`expressNo`、`weight`……）。出现新字段会自动插入新列，旧行该列留空。
  - **图片列直接显示缩略图 + 类型和大小**（如 `PNG · 1.0 MB`），**双击可放大查看**。类型按文件头识别，支持 PNG / JPEG / GIF / BMP / WEBP / PDF，也认 `data:image/png;base64,` 前缀。单张超过 5MB 不落盘，但仍记录类型和大小。
  - 其余超长字段在单元格里折叠成「头部....尾部[N字符]」，悬停可看完整摘要。
  - 选中任意一条点「重发选中」，即可把这条数据**原样**重新推送给所有已连接的前端（双击留给图片放大，避免误触重发） —— 表格里显示的是折叠摘要，重发时用的是完整原始数据（含完整 base64）。
  - 前端调试时不用再让外部系统重新推一次。无客户端连接时重发会提示未送达。
  - **图片存磁盘、不占内存**：收到数据时图片单独写成文件，内存里只留一张小缩略图，其余字段照常保留。
    实测收 200 单、每张图约 1MB：磁盘 207MB，**内存零增长**（RSS 反而略降）；`history.jsonl` 仅 43KB，因为里面不含 base64。
    表格上方实时显示「共 N 条 · 图片 X MB 存在磁盘（不占内存）」。

- **历史持久化**：每收到一条就立刻追加写盘，程序关闭/崩溃都不丢；下次启动自动载入最近 200 条（含缩略图）。

  ```
  logs/                      ← 默认在程序所在目录，不存在会自动创建
    history.jsonl            ← 每行一条元数据（不含图片 base64）
    images/
      20260818_115425_071713.png        ← 原图，重发时从这里读回
      20260818_115425_071713_thumb.png  ← 缩略图，启动时只读它，不必解码原图
  ```

  - 目录可在「接收历史」页签里点「更改目录」切换（记在 `QSettings`，下次启动沿用），「打开目录」直接在访达/资源管理器里打开。
  - 「清空历史」会删除记录和图片文件，因此会先弹窗确认。
  - 超过 200 条时，最旧的记录连同它的图片文件一起删除，磁盘不会无限增长。
- **主题：白天 / 黑夜 / 跟随系统**，右上角分段控件一键切换，选择会记住（`QSettings`），下次启动自动恢复。
  - 选「跟随系统」时，系统在浅色/深色之间切换会实时跟着变，无需重启。
  - 通过 Qt 的 `setColorScheme` 同时切换原生控件（复选框、下拉箭头、滚动条）的配色，不会出现深色背景配浅色控件的割裂感。
  - 配色集中在 `theme.py` 的 `PALETTES` 里，改颜色不用动样式表结构。

## 数据流

```
前端页面 ──WS 二进制(PDF)──▶ websocket_handler ──▶ 系统打印机(lp / ShellExecute)
        ◀──WS print_status──┘

外部系统 ──POST JSON──▶ HTTP :13213/callback ──转发──▶ 前端页面(WS external_data)
```

## 项目结构

| 文件 | 作用 |
| --- | --- |
| `main.py` | 程序入口，启动 Qt 应用和主窗口 |
| `gui.py` | PyQt6 主界面，负责配置、启停服务、日志展示、主题切换 |
| `theme.py` | 白天/黑夜配色 token 与样式表生成，跟随系统的解析逻辑 |
| `history_store.py` | 接收历史落盘：图片存文件、元数据存 jsonl、重发时还原 payload |
| `websocket_server.py` | 启动 WebSocket 服务（asyncio），支持 stop_event 优雅停止 |
| `websocket_handler.py` | 单个 WebSocket 连接的消息处理：打印 PDF、耗时统计 |
| `data_receiver.py` | HTTP 回调服务 + 全局 WebSocket 连接注册与转发 |
| `printer_utils.py` | 打印机枚举、base64 转 PDF、跨平台打印 |
| `logger.py` | 基于队列的日志封装，带时间戳 |

## 环境与依赖

- Python 3.13（项目自带 `.venv`）
- `PyQt6`
- `websockets`
- 打印相关（按平台二选一，需自行安装）：
  - Windows：`pywin32`
  - macOS / Linux：`pycups`（`import cups`）

```bash
pip install PyQt6 websockets
# Windows
pip install pywin32
# macOS / Linux
pip install pycups
```

## 运行

```bash
python main.py
```

1. 勾选需要的功能（默认只开「获取数据」，「自动打印」需手动勾选）。勾选后对应的配置卡片才会出现。
2. 设置 WebSocket 端口；勾选了「自动打印」时再选择打印机。
3. 点击「启动服务器」，日志窗口会显示 WebSocket 与 HTTP 的监听状态。
4. 点击「停止服务器」关闭两个服务。

## 说明与限制

- 启动后会回查端口是否真的绑定成功；被占用时状态栏变红提示并自动回滚到「已停止」，不会显示成运行中。
- WebSocket 监听地址：Windows 上绑定 `localhost`，macOS / Linux 上绑定 `0.0.0.0`。
- 数据获取地址 `localhost:13213/callback` 在界面上是只读的，目前为固定值。
- 待打印的 PDF 写在系统临时目录的 `print_application_server/` 下，超过 24 小时的旧文件会在下次打印时自动清理。
- 日志中超过 60 字符的字段会折叠成「头部....尾部[N字符]」，避免 base64 图片刷屏；**转发给前端的仍是完整数据**。
- 打印本身是阻塞操作，已放到独立线程执行，不会卡住 WebSocket 消息收发。
