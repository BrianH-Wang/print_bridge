# 高级配置设计

配套文档：[对接-几何智造分拣设备.md](对接-几何智造分拣设备.md)（真实用例）

## 进度

| 组 | 状态 | 在哪 |
| --- | --- | --- |
| X1 监听（端口 / method / Content-Type） | 端口 ✅，method 和 Content-Type ❌ | 通道「基础」页 |
| X2 接收与校验（路径表达式、缺失策略、内容校验） | 路径与缺失策略 ✅，内容校验 ❌ | 通道「字段映射」页 |
| X3 出向报文（type / 附加字段 / 自定义模板） | ✅ | 通道「发给前端 ⚙」页 |
| X4 应答外壳（模板 / 状态码策略 / 按场景覆盖） | ✅ | 通道「回给设备 ⚙」页 |
| X5 配对合流 | ✅ | 通道「配对」页 |

| X8 入向识别规则 | ❌ | 三期 |

**X8 没做意味着**：出向报文可以改成任意形状，但前端**回**给我们的仍然必须是
`{"type":"external_reply","id":…}` / `{"type":"ack","id":…}`。前端那侧完全改不动时才需要 X8。

## 0. 三层结构，高级只是最里面那层

```
预设       选「几何智造分拣设备」→ 一键套好，什么都不用填     ← 绝大多数人停在这
 ↓
基础/字段映射页  改路径、改字段名、勾配对                     ← 会看 JSON 就够
 ↓
两页 ⚙     改报文形状、改应答外壳、写模板                     ← 要懂 HTTP + JSON
```

实际落地时高级设置**没有做成一整页**，而是按「去向」拆成两页——
`发给前端 ⚙` 和 `回给设备 ⚙`。一整页往下滚三屏，改哪个方向的东西都得先找一遍；
按去向分之后每页只有半屏，而且"我要改的是发出去的还是回去的"这个问题，
用户自己心里是清楚的。

**这三层的关键不是"把高级功能藏起来"，是让高级配置只需要被配一次。**

对接方（懂技术的那个人）在高级页配好 → **导出成一个 json** → 其他门店/其他机器直接导入。
不会开发的人永远不用打开高级页。

✅ **已实现**：配置方案卡第二行的「导出 / 导入 / 模板」（`config_io.py` + P8）。
内置两套模板：空白起步、几何智造分拣设备。导入重名时弹三选一，绝不静默覆盖。

这也是为什么高级配置值得做全：它不是给每个用户用的，是给**每个对接场景配一次**用的。

## 1. 铁律：高级页所有项的默认值 = 当前行为

全部留空 / 全部默认 = 和今天一模一样。任何一项都能单独「恢复默认」。

这条守不住，高级页就会变成一个碰了就出事的雷区，没人敢开。

## 2. 高级页有什么

通道配置对话框（P7）分「基础 / 高级」两页，高级页按下面 7 组折叠，默认全收起。
每组标题旁边一句话说明「不动它会怎样」。

### X1 监听

| 项 | 默认 | 说明 |
|---|---|---|
| 端口 | 空（用主端口） | 填了就单独起一个 HTTP 服务 |
| 请求方法 | `POST` | 可多选 `GET` / `PUT` / `PATCH` |
| Content-Type | `application/json` | `form` / `raw` / `binary` / `auto` |
| 取值来源 | `body` | 选 `GET` 时自动切 `query` |

> 选 `GET` 时数据在 URL 参数里，且带不了图片——界面要直说，别让人配完才发现。

### X2 接收与校验

| 项 | 默认 | 说明 |
|---|---|---|
| 字段路径 | 顶层字段名 | 高级下可写 `a.b[0].c`、`items.*.sku` |
| 必填缺失时 | `报错` | `报错` / `跳过该字段` / `用默认值` |
| body 上限 | 全局 16MB | 按通道覆盖 |
| 内容校验 | 无 | 字段 + 解码方式 + 大小上限 + 允许类型 |

内容校验就是 `/upload` 那条 2MB + jpg/png/pdf 的来源。识别用现成的
`history_store.sniff()`（`history_store.py:40`），已经认得 jpg/png/pdf。

### X3 出向报文（发给前端的形状）

| 项 | 默认 | 说明 |
|---|---|---|
| 外壳 | `标准` | `标准` = `{"type":..,"id":..,"data":..}`；`自定义` = 你写模板 |
| type 名称 | `external_data` | 前端已有协议时改这里 |
| 固定附加字段 | 无 | 例如 `{"source":"仓库A"}` |

自定义模板示例——前端要平铺、字段名也不一样：

```jsonc
{ "expressNo": "{{code}}", "img": "{{file}}", "seq": "{{__id}}" }
```

> **`{{__id}}` 必须出现在模板里**，否则双向模式下前端回复对不上号。保存时强校验，缺了直接拦。

### X4 应答外壳（回给设备的形状）

这一组是实测差距里第 1、2 条的解药——设备要 `msg`，我们发的是 `message`。

| 项 | 默认 | 说明 |
|---|---|---|
| 模板 | 当前形状 | 内置变量 `{{__success}}` `{{__code}}` `{{__message}}` `{{__data}}` |
| HTTP 状态码 | `跟随 code` | 或 `固定 200`（有些设备只看 body，HTTP 非 200 会被它当网络错误） |
| 按场景覆盖 | 全局表 | 现在的 P5 挪进来，支持按通道覆盖 |

几何智造要的：

```jsonc
{ "success": "{{__success}}", "code": "{{__code}}",
  "msg": "{{__message}}", "data": "{{__data}}" }
```

顺带解决第 2 条：模板里没写 `forwarded`，它就不会出现在返回里。

### X5 配对

| 项 | 默认 | 说明 |
|---|---|---|
| 等另一半 | `5s` | 只有 primary 通道要等 |
| 等不到时 | `照发（标记 partial）` | / `丢弃` / `报错` |
| 同 code 重复 | `后到覆盖` | / `保留先到` / `报错` |
| 暂存上限 | `200 条` | 满了按先进先出丢 |
| 暂存过期 | `60s` | 到点清掉，图片不常驻内存 |
| 暂存落盘 | `关` | 图多时打开，复用 `history_store` 的图片目录 |

> 等图和等前端回复**共用一份超时预算**（照 `data_receiver.py:415` 的 `deadline` 做法），
> 不然设备实际要等 `等图 + 回复超时`，是配置值的两倍。

### X6 回程映射（双向通道才显示）

前端回的字段名和设备要的对不上时用。和正向映射同一套引擎反着跑。

```
前端回  {"格口": "A", "单号": "MO123"}
          ↓  回程映射
设备收  {"route": "A", "mainOrderNo": "MO123"}
```

### X7 条件转发

`when` 满足才处理。不满足时：`丢弃并回 200` / `报错` / `转到别的通道`。

例：`weight` 为 0 的空过机不推给前端，直接回 200。

## 3. 全局高级（方案级，不在通道里）

### X8 入向识别规则

前端已经写死、改不动时用。默认规则 = `websocket_handler.py:39-76` 现在的判断，
不配就是今天的行为。

```jsonc
[
  { "when": {"cmd": "reply"},    "as": "reply",
    "id_from": "seq", "data_from": "payload" },
  { "when": {"action": "print"}, "as": "print",
    "data_from": "content", "printer_from": "device" }
]
```

## 4. 你这台设备，高级页实际要动几项

| 组 | 动什么 |
|---|---|
| X4 应答外壳 | 模板改成 `success/code/msg/data` ← **必改，不改设备解析不了** |
| X4 场景覆盖 | `bad_json`→404、`reply_timeout`/`no_client`→500 |
| X2 内容校验 | `/upload` 的 `file` 字段：base64 解码后 ≤2MB，仅 jpg/png/pdf |
| X4 新场景 | `attach_too_large`→413、`attach_invalid`→415 |
| X5 配对 | 用默认值就行 |
| X1/X3/X6/X7 | **不用动** |

**八组里只有两组是必须动的。** 其余保持默认。

配好导出成 `几何智造分拣设备.json`，下一台机器直接导入——这就是第 0 节说的那件事。

## 5. 防呆

1. 顶部常驻横幅：⚠️ 这些设置需要了解 HTTP 和 JSON。基础页已经够用，不确定就别动这里。
2. **模板编辑器实时校验 + 预览**：左边样例、右边算出来的结果，JSON 写错立刻标红，错的存不进去。
3. 每项独立「恢复默认」，每组一个「整组恢复默认」。
4. 改过的项加一个圆点标记，一眼看出哪几项被动过（对着默认值比，不是对着上次保存比）。
5. 保存时跑一遍硬校验：`{{__id}}` 在不在、模板是不是合法 JSON、引用的字段样例里有没有。

## 6. 明确不做：内嵌脚本

不提供 Python / JS 代码框。

配置是要被导出、被复制到别的门店、被发在群里的。里面存一段可执行代码，
等于谁拿到这份配置就能在这台连着打印机的电脑上执行任意代码。

覆盖不了的需求就加算子（X2 的转换清单），不加 `eval`。
