# 开发指南

跑起来、改代码、打包、发版。功能说明在 [README](../README.md)，
给使用者的手册在 [使用说明](使用说明.md)。

## 一、环境

Python **3.13**。依赖很少，没有构建步骤，改完直接跑。

```bash
python -m venv .venv
.venv/bin/python -m pip install PyQt6 websockets

# 打印相关，按平台装其一（不装也能跑，只是列不出系统打印队列）
.venv/bin/python -m pip install pywin32    # Windows
.venv/bin/python -m pip install pycups     # macOS / Linux
```

> Linux 装 `pycups` 前要先有 `libcups2-dev`（`sudo apt-get install -y libcups2-dev`）。

**`.venv/bin/pip` 这个脚本的 shebang 可能指向别的项目的 venv**（历史遗留）。
统一用 `.venv/bin/python -m pip`，别直接调 `pip`。

## 二、跑起来

```bash
.venv/bin/python main.py
```

界面起来后：勾功能 → 配端口和通道 → 点「启动服务器」。
详细操作见 [使用说明](使用说明.md)。

## 三、代码怎么分层

**核心规则：模型层不依赖 Qt。** 下面四个模块都是纯函数 + 纯数据，
可以脱离界面直接跑、直接单测；界面只负责填表和显示。

```
                    ┌─────────────────────────────────────┐
  设备 / 上游  ──▶  │ data_receiver   HTTP 接收、路由、应答 │
                    └───────┬─────────────────────────────┘
                            │  调用（单向依赖，模型层不反向引用）
              ┌─────────────┼──────────────┬───────────────┐
              ▼             ▼              ▼               ▼
        channels.py    mapping.py     pairing.py     config_io.py
        怎么收         怎么翻译        怎么合流        怎么进出磁盘
        路由/应答外壳  字段映射/出向    暂存/配对       导出/导入/模板
              ▲             ▲              ▲               ▲
              └─────────────┴──────┬───────┴───────────────┘
                                   │  只读取，不反向依赖
                             ui/ 各组件与对话框
```

| 模块 | 行数 | 管什么 |
| --- | --- | --- |
| `channels.py` | 331 | 通道模型、按路径路由、回给设备的应答外壳模板 |
| `mapping.py` | 322 | 路径取值 `a.b[0].c`、转换算子、字段映射、发给前端的报文组装 |
| `pairing.py` | 222 | 配对暂存区、等待与收集、合并规则、过期与上限 |
| `config_io.py` | 177 | 配置导出/导入的格式与校验、内置模板 |
| `selftest.py` | 615 | 配置自测：静态体检 + 按样例真发请求逐项核对，内置假前端 |

这四个模块的校验函数（`validate_envelope` / `validate_outbound` / `map_fields`）
**同时供对话框做实时预览和运行时使用**，所以不会出现"预览通过但运行时报错"。

> 常量下沉到 `channels.py`（`ONEWAY`/`TWOWAY`/`RESPONSE_DEFAULTS` 等），
> `data_receiver` re-export 一份，老的 `from data_receiver import TWOWAY` 照常能用。
> 这么绕是为了断开循环引用：`data_receiver` 要 import `channels` 来路由。

### 服务层

| 模块 | 行数 | 管什么 |
| --- | --- | --- |
| `data_receiver.py` | 670 | HTTP 接收服务；WebSocket 客户端注册与广播；ack / 双向回复的等待槽；单发排队 |
| `websocket_server.py` | 39 | 起 asyncio WebSocket 服务，`stop_event` 优雅停止 |
| `websocket_handler.py` | 199 | 单条连接的消息处理：打印、ack、`external_reply`、耗时统计 |
| `printer_utils.py` | 209 | 打印机枚举、跨平台打印、网络直连 RAW 9100、连通性探测 |
| `history_store.py` | 202 | 接收历史落盘：图片存文件、元数据存 jsonl、重发时还原 |
| `logger.py` | 42 | 基于队列的日志，工作线程写、GUI 线程读 |
| `theme.py` | 384 | 白天/黑夜配色 token 与样式表生成 |

### 界面层

`gui.py` 只剩 8 行转发，界面都在 `ui/` 包里。

| 模块 | 行数 | 管什么 |
| --- | --- | --- |
| `ui/main_window.py` | 528 | 主窗口：拼装各配置卡与页签 |
| `ui/profiles.py` | 416 | 配置方案（mixin）：增删改、切换、导出/导入/模板 |
| `ui/server_control.py` | 153 | 启停服务与各项校验（mixin） |
| `ui/channel_list.py` | 250 | 接收通道表格 + 增删改 + 跨通道配对校验 |
| `ui/printer_list.py` | 223 | 打印机表格 + 增删改 + 设为默认 |
| `ui/constants.py` / `ui/helpers.py` | 74 / 209 | 界面常量；纯函数（`sanitize_*` 系列在这里） |
| `ui/panels/` | 900 | 日志、接收历史、自测三个页签 |

`ui/dialogs/channel.py`（740 行）是最大的一个——通道对话框有五页。
它把「字段映射」那页拆给了 `field_mapping.py`，因为那页自带表格、样例、预览三块。

## 四、本地联调

**一条命令把一份配置跑一遍**（推荐先用这个）：

```bash
.venv/bin/python tools/selftest.py --config configs/几何智造分拣设备.json
```

它先做静态体检（配对字段是不是转译后的名字、应答外壳缺不缺 msg、
两条通道的样例条码对不对得上），再按每条通道的 `sample` 真发请求，
逐项核对 HTTP 状态码、应答 body、前端收到的报文、配对有没有合成一条。
预期值全部从配置算出来，不用人填。

- 没有服务在跑：它自己在进程里起一套，跑完就停。
- 已经开着 Print Bridge：直接打它。没前端连着就起内置假前端按通道的
  `reply_sample` 回；有真前端连着就只旁观，测的是整条链路。
- `--list` 只列用例；`--no-negative` 跳过坏 JSON / 缺字段 / 错路径；
  `--slow` 加跑"前端不回复"的超时用例（每条要等满 timeout 秒）；`--json` 给脚本用。
- 自测的请求带 `X-Print-Bridge-Selftest: 1` 头：走完整条链路，但不进接收历史，日志上有 🧪。
- 界面里的「自测 🧪」页签调的是同一个 `selftest.run`，边跑边刷新，点一条能看原始报文。

手动分步跑的话，`tools/` 下还有两个脚本，不依赖真实设备和前端页面：

```bash
# 假前端：连上 WS，收到数据就回一条结果（浏览器还没开发好时顶上）
.venv/bin/python tools/mock_frontend.py --port 8765

# 假设备：按接口文档打两条请求进来，并逐条校验返回结构
.venv/bin/python tools/mock_device.py
```

常用变体：

```bash
# 配对：两种到达顺序都该合并成一条
tools/mock_device.py                                  # 附件先到
tools/mock_device.py --order data-first --parallel    # 主数据先到
tools/mock_device.py --no-image                       # 只发主数据，测配不上时的表现

tools/mock_frontend.py --no-reply        # 前端不回，测设备侧超时
tools/mock_frontend.py --delay 3 --pdf   # 前端慢 3 秒，回复带 PDF
```

> **`--parallel` 不是可选项而是必需项**：配对模式下 `/callback` 会阻塞等附件，
> 顺序发的话那条附件永远轮不到发出去。这个坑对真实设备同样成立，
> 见 [README](../README.md#配对合流两条链接合成一条每条通道单独配) 里的警告。

不开界面跑服务（用来对着上面两个脚本验后端）：

```python
import data_receiver, threading
from channels import TWOWAY, make_channel
from websocket_server import start_websocket_server

data_receiver.configure_channels([make_channel("data", path="/callback", flow=TWOWAY)])
stop = threading.Event()
threading.Thread(target=start_websocket_server, args=(8765, [], stop), daemon=True).start()
threading.Thread(target=data_receiver.start_http_server, args=("127.0.0.1:13213",), daemon=True).start()
```

### 写测试要注意

GUI 测试**必须把 `QSettings` 隔离到临时文件**，否则会写进用户真实的偏好设置。
macOS 上 `QSettings.setPath()` 对 NativeFormat 无效，只能替换构造：

```python
import PyQt6.QtCore as QtCore
_real = QtCore.QSettings
class FakeSettings(_real):
    def __init__(self, *a, **k):
        super().__init__(INI_PATH, _real.Format.IniFormat)
QtCore.QSettings = FakeSettings
import ui.main_window as mw
mw.QSettings = FakeSettings      # 模块里已经 from 进去的那个引用也要换
```

跑 GUI 测试设 `QT_QPA_PLATFORM=offscreen`。

## 五、打包

```bash
.venv/bin/python -m pip install pyinstaller markdown   # markdown 用来把使用者手册转成 HTML
.venv/bin/python -m PyInstaller --noconfirm print_bridge.spec
bash scripts/make_dmg.sh          # macOS 额外打 DMG
```

产物：

| 平台 | 产物 | 体积参考 |
| --- | --- | --- |
| macOS | `dist/Print Bridge.app`、`dist/Print Bridge.dmg` | 75 MB / 30 MB |
| Windows | `dist/print_bridge/print_bridge.exe` | 25–30 MB |
| Linux | `dist/print_bridge/print_bridge` | 25–28 MB |

**PyInstaller 不支持交叉编译**，三个平台的包必须各自在目标系统上构建。

### 随包带出去的配置文件

仓库根目录的 `configs/` 放现成的配置文件（如 `几何智造分拣设备.json`），
spec 在 COLLECT 之后把它整个拷到 `dist/print_bridge/configs/`，
`make_dmg.sh` 再把它放到 DMG 里和 .app 并排。故意不走 `datas`——那会埋进
`_internal/` 或 .app 内部，使用者找不到。程序里「导入」对话框会默认打开到这个
文件夹（`config_io.bundled_configs_dir()`），找不到就退回系统默认目录。
往里加文件即可，不用改 spec。

使用者手册也走这条路，但发出去的是 HTML：`scripts/build_manuals.py` 把
`docs/使用说明.md`、`docs/高级配置说明.md`（中文）和 `docs/User Guide.md`、`docs/Advanced Guide.md`（English）
转成 `build/manuals/*.html`，spec 和 `make_dmg.sh` 再把这四个 .html 拷到可执行文件旁边（macOS 是 DMG 里和 .app 并排）。
使用者的电脑上没有看 .md 的东西，.html 双击就能开。仓库里只维护 Markdown，HTML 不进仓库。
只带这四份——开发指南、高级配置（设计稿）、对接案例是给开发者看的，看仓库里的就够了。

### spec 里没有写死的模块清单

`print_bridge.spec` 只分析 `main.py`，靠静态 import 图自动收集。
新加顶层模块**不用改 spec**，但值得确认一下它真的可达：

```bash
.venv/bin/python - <<'EOF'
import ast, pathlib
ROOT = pathlib.Path(".").resolve()
local = {p.relative_to(ROOT).with_suffix("").as_posix().replace("/", ".").removesuffix(".__init__")
         for p in ROOT.rglob("*.py")
         if not any(x in p.parts for x in ("build", "dist", ".venv", "__pycache__", "tools"))}
seen, stack = set(), ["main"]
while stack:
    mod = stack.pop()
    if mod in seen or mod not in local:
        continue
    seen.add(mod)
    path = ROOT / (mod.replace(".", "/") + ".py")
    if not path.exists():
        path = ROOT / (mod.replace(".", "/") + "/__init__.py")
    for node in ast.walk(ast.parse(path.read_text(encoding="utf-8"))):
        if isinstance(node, ast.Import):
            stack += [a.name for a in node.names]
        elif isinstance(node, ast.ImportFrom) and node.module and node.level == 0:
            stack.append(node.module)
            stack += [f"{node.module}.{a.name}" for a in node.names]
print("不可达（不会被打进包）:", sorted(local - seen) or "无")
EOF
```

正常输出只会列出 `gui`（向后兼容的转发 shim，没人 import）和 `ui`（包 `__init__`，
被隐式导入，这个遍历不记父包）。出现别的名字就要查了。

## 七、分发时会被拦

### macOS

没有 Apple Developer 签名时首次双击会被 Gatekeeper 拦下，任选其一处理：

```bash
# 1) 自己/团队内部用：删掉隔离属性，以后不再被拦
xattr -dr com.apple.quarantine "/Applications/Print Bridge.app"

# 2) 访达里按住 Control 点 → 「打开」→ 弹窗再点「打开」，系统之后就记住了

# 3) 正式分发：申请 Apple Developer ID（年费），codesign + notarytool 公证
```

首次启动系统防火墙会问是否允许接受网络连接（程序要监听 HTTP 和 WebSocket 端口），
**必须点「允许」**。

### Windows

SmartScreen 弹「Windows 已保护你的电脑」→「更多信息」→「仍要运行」，只在首次出现。
Defender 防火墙首次也会问，勾哪个网络都行。

### Linux

一般不用特别处理，直接 `./print_bridge/print_bridge`。
SELinux 拦端口时会报 `permission denied`，临时 `setenforce 0` 可以排除这个因素。

## 八、已知的坑

| 坑 | 现状 | 影响 |
| --- | --- | --- |
| **入向协议还不能自定义** | 出向报文可以任意改形状，但前端**回**给我们的仍必须是 `{"type":"external_reply","id":…}` / `{"type":"ack","id":…}` | 前端那侧完全改不动时对接不了，见 [高级配置.md](高级配置.md) 的 X8 |
| **上游顺序发则配对必失败** | 见第四节 `--parallel` 那段 | 只能让上游先发附件，或两条请求各用各的连接 |

### 已经修掉的（留个记录，别再踩回去）

- **历史目录不能放程序旁边**。`default_dir()` 现在返回系统用户数据目录
  （macOS `~/Library/Application Support/Print Bridge`、Windows `%LOCALAPPDATA%`、
  Linux `~/.local/share/print-bridge`），**开发态和打包态用同一个位置**，
  省得"开发时好好的，打包就出事"。`legacy_dir()` + `migrate_legacy()` 负责
  把老版本留在程序目录下的数据搬过来，只在新位置还没数据时搬，绝不覆盖。
- **`pycups` 缺失不再等于打印机列不出来**。`_printers_via_lpstat()` 用
  `lpstat -p` / `lpstat -d` 兜底——打印本身走的就是 `lp -d`，装了 CUPS 就有 lpstat。
  顺带修正：pycups 的 `getDefault()` 给的是**用户**默认打印机，没单独设过是 `None`，
  系统默认得问 `lpstat -d`，不补这一下界面上不会预选任何一台。
- **历史从来没在启动时载入过**。`_load_history()` 只在「修改目录」时被调用，
  构造函数里漏了——磁盘上明明有记录，界面每次启动都是空的，而文档还写着会自动载入。

## 九、行为上的几个约定

- 启动后会**回查端口是否真的绑定成功**；被占用时状态栏变红并回滚到「已停止」，不会假装在运行。
- WebSocket 监听地址：Windows 绑 `localhost`，macOS / Linux 绑 `0.0.0.0`。
- 待打印的 PDF 写在系统临时目录的 `print_bridge/` 下，超过 24 小时的旧文件在下次打印时清理。
- 日志中超过 60 字符的字段折叠成「头部....尾部[N字符]」，避免 base64 刷屏；
  **转发给前端的仍是完整数据**。
- 打印是阻塞操作，放在独立线程跑，不卡住 WebSocket 消息收发；
  同一台打印机串行、不同打印机并行（每台一把锁，不是一把全局锁）。
- 单发模式下**排队和等回复共用同一份超时预算**，设备最多等配置的那个秒数。
  配对模式下「等附件」和「等前端回复」同理共用一份。
