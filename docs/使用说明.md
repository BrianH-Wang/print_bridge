# Print Bridge 使用说明

给使用者看的操作手册。不需要懂编程，照着做就行。
开发相关的内容在 [README](../README.md)，界面元素编号在 [UI.md](UI.md)。

---

## 一、这个程序是干什么的

浏览器里的网页**不能直接连打印机**，也**不能被外部系统主动推数据**。
Print Bridge 装在这台电脑上补这两件事：

```
        ┌──────────────────────────────────┐
上游 ──▶ │  Print Bridge                    │ ──▶ 浏览器页面
(设备/    │  收数据、翻译字段、合并、转发      │
 系统)    │                                  │ ◀── 打印指令
        └──────────────┬───────────────────┘
                       └──────▶ 打印机
```

它同时做两件事，可以只开一件：

| 功能 | 做什么 |
| --- | --- |
| **获取数据** | 上游系统把数据发到本机，本程序转给浏览器页面 |
| **自动打印** | 浏览器页面把要打的内容发过来，本程序交给打印机 |

> 本程序只在**这台电脑内部**做中转，不往外网发任何东西。

## 二、第一次打开

### 启动

双击程序图标即可，不用装其他东西。

**如果被系统拦住：**

- **macOS** 提示「无法打开，因为无法验证开发者」
  → 在访达里**按住 Control 点**程序图标 → 选「打开」→ 弹窗里再点一次「打开」。
  只需做这一次，之后双击就能进。
- **Windows** 提示「Windows 已保护你的电脑」
  → 点「更多信息」→「仍要运行」。
- 首次启动**防火墙会问是否允许网络访问** → 必须点「允许」，
  否则上游发不进来、浏览器也连不上。

### 界面长什么样

顶部常驻**启动/停止按钮**和**状态条**，不管在哪个页签都能看到、都能操作。

下面是三个页签：

| 页签 | 什么时候看 |
| --- | --- |
| **配置 ⚙** | 装机时设一次，之后基本不用动 |
| **日志输出 📋** | 日常盯这个，每条收发都有记录 |
| **接收历史 📜** | 查历史数据、看图片、重新发给页面 |

右上角可以切换**白天 / 黑夜 / 跟随系统**，选了会记住。

## 三、五分钟跑通

最省事的路径是**用模板**，不要从空白开始填。

### 1. 建一套配置

「配置」页签 →「配置方案」卡片 →「配置文件: **模板**」

弹窗里选一个模板，看下面的预览确认是你要的，点「**直接套用**」。
这会新建一套方案并切过去。

> 如果对接方给了你一个 `.json` 配置文件，改点「**导入**」选中它，效果一样。

### 2. 确认三件事

| 位置 | 确认什么 |
| --- | --- |
| 功能选择 | 要收数据就勾「获取数据」，要打印就勾「自动打印」 |
| 前端连接 | WebSocket 端口，告诉写页面的人用哪个 |
| 获取数据配置 | 监听地址，告诉上游往哪儿发 |

### 3. 点「启动服务器」

按钮变红、状态条显示「服务运行中」就成了。

切到「日志输出」，应该能看到：

```
✅ WebSocket 监听启动: ws://0.0.0.0:8765
🔁 接收通道 2 条：
   · order_data 主数据 ← /data（双向）· 并发 · 超时 15s · 自定义应答外壳
🌐 HTTP 监听启动: http://0.0.0.0:13213
```

### 4. 确认真的通了

- 浏览器页面连上时，日志会打印 `🌐 WebSocket 客户端已连接`
- 上游发来数据时，日志会打印 `📥 [通道名] 接收数据: ...`，
  「接收历史」页签的标题数字也会 +1

两条都看到，就是通了。

## 四、按需要配置

以下都在「配置」页签里，**改完记得点「保存」**，否则切换方案时会丢。
提示行会写「已保存」还是「有未保存的修改」。

> 服务运行中大部分设置是锁住的，要改先点「停止服务器」。

### 4.1 前端连接端口

写页面的人需要知道这个地址：`ws://本机IP:端口`，默认端口 8765。
提示行会把完整地址写出来，直接复制给他。

### 4.2 添加打印机

「自动打印配置」→「添加」。

| 填什么 | 说明 |
| --- | --- |
| **Key** | 英文名，页面用它指定打给哪台，如 `receipt`、`kitchen` |
| **备注** | 中文，只给你自己看 |
| **方式** | 「系统打印机」= 电脑里已装好的队列（USB / 蓝牙 / WiFi / 网口都算）<br>「网络直连」= 直接连打印机 IP，不经系统队列 |
| **目标** | 系统打印机选队列名；网络直连填 `IP:端口`（一般 9100），可点「测试连接」 |

**第一台就是默认打印机**（表格里标 ★）。页面不指定打给谁时用它。
想换默认的，选中另一行点「设为默认」。

### 4.3 添加一条接收链接

「获取数据配置」→「添加」。每条上游接口对应一条**通道**。

**基础**页填这些：

| 填什么 | 说明 |
| --- | --- |
| **Key** | 英文名，页面靠它区分数据来自哪条链接 |
| **路径** | 上游发送地址里 `/` 后面那段，如 `/data`。<br>填 `*` 表示**兜底**：其余没人认领的路径都归它 |
| **数据流** | **单向** = 收下就回，不等页面<br>**双向** = 等页面回一条结果，再拿它答复上游 |
| **超时** | 双向时上游最多等多久 |

填完看下半部分的**「这条通道怎么用」**——那里有一条现成的命令，
可以直接发给对接方，让他照着调。

> **什么时候用双向？** 上游需要拿到一个由业务系统算出来的结果才能继续
> （比如要回一个编号、一个状态）。只是把数据送进来就用单向。

### 4.4 字段名对不上怎么办

上游发来的叫 `no`，页面要的叫 `orderNo`，两边都改不动——在「**字段映射**」页翻译。

**最省事的做法：**

1. 让对接方发一条真实数据给你，**粘进下面的「样例」框**
2. 点「**按样例填充**」——所有字段自动列出来了
3. 只改「目标字段」那一列，写成页面要的名字
4. 模式选「**只保留下面映射的字段**」
5. 看下面的**预览**，右边就是页面将收到的内容

「转换」那一列是可选的，常用的有：

| 转换 | 什么时候用 |
| --- | --- |
| 去掉首尾空格 | 上游偶尔多带空格 |
| 转数字 | 上游把重量发成文字 `"12.50"`，页面要数字 `12.5` |
| 转大写 / 转小写 | 单号大小写不统一 |
| 毫秒/秒时间戳 → 日期时间 | 上游发 `1767225600000`，页面要 `2026-01-01 12:00:00` |

「必填」勾上后，上游没发这个字段时会按上面的策略处理（默认是回错误给上游、不转发）。

### 4.5 两个接口合成一条

上游把一件事拆成两个接口发（比如**图片**一个接口、**主数据**另一个接口），
靠同一个业务号关联。页面要的是一条完整记录，不是两条对不上的消息。

在两条通道的「**配对**」页各设一次：

| 通道 | 角色 | 还要填 |
| --- | --- | --- |
| 主数据那条 | **主报文** | 最多等附件多久（默认 5 秒）、等不到时照发还是回错误 |
| 附件那条 | **附加数据** | 暂存多久（默认 60 秒） |

两条的「**配对组**」要填成同一个，「**配对字段**」也要一样。

> ⚠️ **配对字段填的是「字段映射」翻译之后的名字**。
> 如果两条通道原本的字段名不同（一边 `no`、一边 `orderNo`），
> 先在各自的「字段映射」里改成同一个，这里才对得上。

谁先到都行。设成「附加数据」的那条会自动锁成单向——它收下就回，不单独推给页面。

点「启动服务器」时会检查配对是否成对，缺一半会明确告诉你缺什么。

### 4.6 回给上游的内容格式不对

上游的接口文档要求返回的字段叫什么、状态码是多少，如果和默认的对不上：

- **改状态码和文字**：「获取数据配置」→「HTTP 响应」按钮，按场景逐条改。
  这是全局的，运行中也能改，点确定立即生效。
- **改整个返回格式**（比如要求字段叫 `msg` 而不是 `message`）：
  通道的「**回给设备 ⚙**」页 → 勾「自定义应答外壳」→ 从「常用形状」下拉里挑一个。

> 带 ⚙ 的两页需要看得懂 JSON。**不确定就别动**——保持默认是安全的。
> 这两页通常由对接方配一次，配好导出给你，你导入即可。

## 五、把配置给同事 / 换一台电脑

「配置方案」卡片的第二行：

| 按钮 | 什么时候用 |
| --- | --- |
| **导出** | 把当前这套配置存成一个 `.json`，发给同事或留个备份 |
| **导入** | 把别人给的 `.json` 装进来 |
| **模板** | 从内置的成品配置开始 |

- 导出的是**你现在屏幕上看到的样子**，不是上次保存的。
- 导入时如果重名，会问你是**覆盖**、**另存为新的一套**、还是**取消**，不会偷偷盖掉。
- 导出内容包含：端口、监听地址、打印机、全部通道（含字段映射和配对）、返回格式设置。

> 这是最省事的装机方式：**让懂技术的人配好一台，导出，其余电脑全部导入。**
> 其他人不用打开那两页 ⚙。

**多套配置**：一台电脑可以存多套方案（比如「仓库A」「仓库B」），
下拉一选整套就换掉。常用的那套点「设为默认」，开机自动载入（名字前有 ★）。

## 六、日常使用

### 日志输出

每条收发都有记录，出问题先看这里。常见的几行：

| 日志 | 意思 |
| --- | --- |
| `🌐 WebSocket 客户端已连接` | 浏览器页面连上了 |
| `📥 [通道名] 接收数据` | 上游发来数据了 |
| `📤 已推送给 N 个 WebSocket 客户端` | 转给页面了，N 是当前连着几个页面 |
| `↩️ 前端回复` | 双向模式下，页面把结果回来了 |
| `🖨 打印任务 → ...` | 正在打印 |
| `⚠️` / `❌` 开头 | 出问题了，后面跟着原因 |

可以关掉「自动滚动」停住看，也可以一键清空（只清屏幕，不影响历史记录）。

### 接收历史

每条收到的数据都记在这里，最新的在最上面，**最多保留 200 条**。

- 列是按收到的字段自动生成的，来了新字段会自动加一列。
- **图片直接显示缩略图**，双击可放大。
- 选中一行点「**重发选中**」，可以把这条数据重新推给页面——
  调试页面时不用再麻烦上游重发一次。
- 「**打开目录**」在访达/资源管理器里打开存放位置，
  「**修改目录**」换个地方存。

程序关掉再开，历史还在。超过 200 条时最旧的会连同图片一起删掉，磁盘不会无限涨。

> 界面上**没有「清空历史」按钮**。要整批清掉，换一个存储目录，或者直接删掉那个文件夹。

## 七、出问题怎么办

### 服务起不来

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 日志 `❌ 无法启动…端口被占用` | 端口被别的程序占了 | 换一个端口号，记得通知对接方 |
| 点启动后状态条变回「已停止」 | 同上，或地址填错 | 看日志最后一行的具体原因 |
| 弹窗「还没有配置接收通道」 | 勾了「获取数据」但一条通道都没有 | 加一条，或用模板 |
| 弹窗说配对组缺一半 | 只设了主报文或只设了附加数据 | 按提示把另一条也设上，或都改回「不参与配对」 |

### 上游发不进来

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 上游报连接失败 | 服务没启动 / 防火墙拦了 / 地址写错 | 确认状态条是「运行中」；监听地址填 `0.0.0.0` 可让局域网其他机器访问 |
| 上游收到 `404` | 它发的路径没有对应通道 | 加一条路径匹配的通道，或加一条路径填 `*` 的兜底通道 |
| 上游收到 `400` 字段转译失败 | 必填字段它没发 | 看日志里写的是缺哪个字段；确认字段名拼写，或把「必填」取消 |
| 上游收到 `503` 无客户端连接 | 双向模式下没有页面连着 | 先把页面打开 |
| 上游收到 `504` 等待回复超时 | 页面收到了但没回，或处理太慢 | 让写页面的人确认有没有回；或把超时调大 |
| 上游收到 `504` 配对超时 | 另一条链接的数据没来 | 见下 |

### 配对没生效（页面收到两条，或缺字段）

按顺序查：

1. 两条通道的「**配对组**」填的是不是同一个？
2. 两条的「**配对字段**」是不是同一个名字？注意是**翻译之后**的名字。
3. 那个字段在两条数据里**都有值**吗？（在「字段映射」页的预览里能看到）
4. 上游是不是**用同一个连接顺序发**的？
   如果它先发主数据、等回复、拿到回复才发附件——那附件永远发不出去。
   让对接方**先发附件**，或者两条请求各用各的连接。

### 打印没反应

| 现象 | 怎么办 |
| --- | --- |
| 打印机下拉是空的 | 先在系统设置里把打印机装好，再回来点「刷新」 |
| 启动时提示「队列在本机不存在」 | 换了电脑或打印机改名了，编辑那台重新选一次 |
| 日志显示打印失败 | 看后面的具体原因；网络直连的可以用「测试连接」确认通不通 |

## 八、配置和数据存在哪

### 配置

跟着**电脑登录账号**走，不在程序文件夹里，所以**升级或替换程序不会丢配置**。

| 系统 | 位置 |
| --- | --- |
| macOS | `~/Library/Preferences/com.printbridge.PrintBridge.plist` |
| Windows | 注册表 `HKEY_CURRENT_USER\Software\PrintBridge\PrintBridge` |
| Linux | `~/.config/PrintBridge/PrintBridge.conf` |

**备份配置最省事的办法是点「导出」存个 `.json`**，不用去翻上面这些位置。
换电脑时在新机器上「导入」即可。

### 接收历史和图片

在「接收历史」页签顶部能看到当前位置，点「修改目录」可以换。

```
logs/
  history.jsonl        每行一条记录（不含图片）
  images/              图片原图和缩略图
```

> ⚠️ **默认位置是程序旁边的 `logs` 文件夹**。如果你把程序放在
> `应用程序` / `Program Files` 这类目录下，那里通常**不允许写入**，历史会存不进去；
> 就算能写，替换程序时也会被一起删掉。
>
> **建议装好后第一件事就是把存储目录改到「文档」或专门建的文件夹下。**

## 附录：名词对照

| 词 | 意思 |
| --- | --- |
| **上游** | 给本程序发数据的一方（设备、其他系统） |
| **前端 / 页面** | 浏览器里那个网页 |
| **通道** | 一条接收链接的配置。一个上游接口对应一条 |
| **方案** | 一整套配置的打包。一台电脑可存多套，一键切换 |
| **单向 / 双向** | 收下就回 / 等页面回一条结果再答复上游 |
| **配对** | 把两条链接的数据按同一个业务号合成一条 |
| **字段映射** | 把上游的字段名翻译成页面要的字段名 |
| **应答外壳** | 回给上游的那段内容的格式 |
